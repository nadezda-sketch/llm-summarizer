# Отчет о тестировании (TESTING)

Для подтверждения работоспособности сервиса были проверены основные сценарии работы, включая обработку ошибок и работу кеша. Все проверки проводились локально на `http://localhost:8000/docs` (Swagger UI) и через терминал.

## Сценарии тестирования

### 1. Корректный сценарий (Успешный запрос)
*   **Действие:** Отправлен POST-запрос на `/summarize` с валидным текстом про Мировой океан.
*   **Ожидаемый результат:** Статус `200 OK`, в ответе поле `"summary"` содержит краткий пересказ, `"cached": false`.
*   **Фактический результат:** Успешно. В логах сервиса появилось событие `"event": "llm_ok"` и время ответа (около 1.5 сек).

### 2. Ошибка валидации (Некорректный ввод)
*   **Действие:** Отправлен POST-запрос с пустым полем `"text": ""`.
*   **Ожидаемый результат:** Статус `422 Unprocessable Entity`, ошибка валидации Pydantic.
*   **Фактический результат:** Успешно. Сервис вернул 422 и не отправил запрос в LLM (в логах зафиксировано `422 Unprocessable Content`).

### 3. Работа кеша (Повторный запрос)
*   **Действие:** Повторно отправлен тот же текст, что и в п.1.
*   **Ожидаемый результат:** Статус `200 OK`, в ответе `"cached": true`. Ответ приходит быстрее (без запроса к LLM).
*   **Фактический результат:** Успешно. В логах появилось событие `"event": "cache_hit"`.

### 4. Fallback (Сбой внешнего вызова)
*   **Действие:** В файле `.env` был намеренно испорчен API-ключ (добавлен лишний символ), после чего отправлен запрос с новым текстом.
*   **Ожидаемый результат:** Сервис не падает с ошибкой 500, а возвращает статус `200 OK` с текстом заглушки и флагом `"fallback": true`.
*   **Фактический результат:** Успешно. Яндекс вернул ошибку `400 Bad Request`, наш `try/except` перехватил её, и клиент получил корректный Fallback-ответ. В логах зафиксировано `"event": "fallback"`.

## Автоматизированное тестирование (Pytest)
Для проверки бизнес-логики написаны Unit-тесты с использованием `pytest`. Внешние вызовы LLM замоканы (заменены заглушками) для независимости тестов от сети.

Запуск: `pytest -q`
Результат: **6 passed** (все тесты пройдены).

## CI (Continuous Integration)
В проекте настроен пайплайн GitHub Actions (`.github/workflows/ci.yml`).
При каждом пуше запускаются:
1. Линтер `Ruff` (проверка стиля кода).
2. Тесты `Pytest` (проверка логики).
3. Проверка сборки (успешный импорт модуля `main.py`).

**Статус CI:** Все проверки успешно пройдены (зеленая галочка в Pull Request).
